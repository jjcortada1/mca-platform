# Cortada CRM — Full System Audit (July 2026)

Three independent audit passes (UX & visual consistency · code health &
duplication · feature redundancy & information architecture) over all 28 app
pages, 100+ API routes, and shared libraries. Every finding verified in
source. Condensed copy — the full styled report is published as an artifact.

**Verdict:** the data layer and security are solid (101-route tenant-isolation
audit, race-proof saving, silent refreshes with regression tests). The
problems are unification and finish: the same money is typed into multiple
disconnected screens, the same logic is copy-pasted with drift, and half the
UI still assumes the light theme.

## CRITICAL — fix first (Phase 1)

1. **Double-booked commissions** — funded-email approval re-funds an
   already-funded deal and inserts a second commission (or duplicate deal if
   unlinked). `api/funded-approvals/[id]/route.ts`. Fix: dedupe/upsert +
   admin warning.
2. **Dashboard contradicts itself** — KPIs/trend read manual `funded_entries`
   while Portfolio overview reads `deals`. Fix: deals as the single source.
3. **Commissions dark-theme rendering bug** — styled-jsx `var(--input,#e5e7eb)`
   is invalid CSS (vars hold HSL triples), declarations dropped → invisible
   header text / unstyled selects. `commissions/page.tsx:1224,806`.
4. **Calculator commission math diverges from lib** — no epsilon, no 12% cap,
   no default-rules fallback (silent 0% on fetch failure).
   `calculator/page.tsx:104-112` vs `lib/calculator/mca.ts:38`.
5. **Crash vector** — `setDeals(dRes.data ?? dRes ?? [])` puts error objects
   into array state. `active-deals/page.tsx:145`, `funders/page.tsx:104`.
6. **Error-message leak** — `lib/api/response.ts` returns raw `err.message`
   on 500 for 10 routes; migrate to `apiError`, delete file.

## STRUCTURAL (Phase 2 — highest value)

- **Funded data is typed up to 4× per deal** (Mark Funded, Funded Board,
  commission entry, funded-email approval) with no reconciliation; the board
  uses free-text initials that can't join back to deals. Fix: funded
  transition on `deals` auto-derives leaderboard, dashboard, celebration, and
  a draft commission; board kept only as an "off-platform" escape hatch.
- **Commissions/Payments/Accounting split-brain** — payments created in two
  places, edited in a third, listed on all three. Fix: one Payouts area;
  Accounting keeps funder-side cash only.
- **Two post-funding state systems** — legacy `status` values vs
  `fundedSubStatus` vs `paidOff` boolean allow contradictions. Fix: 4 active
  statuses + one sub-status; reject legacy values on write.
- **Settings: 19 tabs, 3,539 lines, renders /account twice** (imported whole
  as a tab + overlapping Security tab). Fix: dedupe tabs, split per-section
  files.
- **Naming**: Funded Board vs Funded Deals (same icon), esign triple-naming,
  "Merchant Funding Estimator" is a reverse-engineering tool, "View as…"
  previews only commissions; sidebar has 3× DollarSign, 3× FileText icons.
- **Dashboard quick actions** link to retired `/submit` (redirect chain);
  two tiles for one merged page.

## DARK-THEME DEBT (Phase 3)

~300 light-only color classes (`bg-amber-100 text-amber-800`…) across 15
files with zero `dark:` variants — worst: portfolio (69), active-deals (48,
whole tone map), deal-shop (45), calculator (36), info (35),
portfolio-dashboard (22, landing page), commissions (21), lead-source-portal,
login/reset. Fix once: shared dual-theme `toneClasses()` next to
`DEAL_STATUS_META`, adopted everywhere (replaces 5 drifting copies).

## CONSISTENCY DEBT (Phase 3)

- ~75 raw `<select>`s bypassing the Select primitive (3 heights on one page)
- ~12 independent money formatters; 4 date systems (20+ raw
  `toLocaleDateString()` sites risking timezone shifts)
- 6 copy-pasted drag-and-drop implementations → one `useReorderableList`
- API envelope chaos (`{data}` vs `{deals,data}` vs named keys) → 20+
  defensive unwraps; standardize on `{data}`
- Loading/empty states split (skeletons on ~10 pages, bare text on ~20)
- No sticky headers on the 5 widest tables
- `BUSINESS_DAYS_PER_WEEK` ×4; two components named `PortfolioDashboard`

## DEAD CODE (~700+ verified lines, Phase 3)

Global search + `/api/search` (312 lines, zero refs) · dead refi-prefill
consumer in active-deals (~40 lines, producer removed) · `/deal-shop/submit`
→ `/submit` redirect chain · orphaned `/api/calculator/*`,
`/api/branding/public` · dead exports: `sendDealEmail` (~110),
`computeDealBreakdown`+friends (~115), `sanitizeCssColor` ×2, 8 unused zod
schemas · decorative-only calculator lock toggles.

## SEQUENCE

Phase 1 critical bugs → Phase 2 money-flow unification → Phase 3
consistency + dark sweep + dead-code deletion → Phase 4 page rebuilds
(Shop & Submit / Active Deals from zero, Settings split).
